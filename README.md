
# AI-помощник для диагностики проблем комнатных растений

**Практический кейс: сценарии диалогов, контроль достоверности ответов и тестирование AI-бота в MAX**

**Статус проекта:** прототип в разработке и тестировании. Стабильная работа бота в мессенджере пока не подтверждена. Этот кейс описывает выполненную работу над логикой ответов, а не готовый коммерческий сервис.

## Задача

Создать AI-помощника «Сфагнум. Север.», который помогает пользователю разобраться с проблемой комнатного растения по фотографии и описанию. Важная часть задачи — не просто дать правдоподобный ответ, а **избежать уверенных выдуманных диагнозов**, когда изображение не позволяет установить причину.

## Моя роль

- Формулирование требований к пользовательским ответам и тону общения.
- Проектирование диалога: выбор задачи, обработка фото, уточнение важных деталей.
- Работа над промптами и структурой выдачи.
- Ручное тестирование сценариев, сравнение фактических ответов с ожидаемыми, выявление ошибок.
- Уточнение правил, при которых бот должен честно сообщить о недостатке данных.

## Что предусмотрено в прототипе

В исходном проекте есть сценарии: «Что с растением?», определение растения, рекомендации по уходу, проверка вариегатности и общие вопросы о комнатных растениях.

В логике предусмотрены следующие ограничения:

1. Сначала описать **наблюдаемые признаки**, затем отдельно представить возможные причины.
2. Сохранять несколько гипотез, если признаки не позволяют выбрать одну.
3. Для проверяемых ботанических утверждений предусмотреть отдельную проверку по внешним источникам.
4. Не подменять неопределённость ложной уверенностью, если источник не подтвердил гипотезу.
5. Задавать **один полезный уточняющий вопрос** только тогда, когда ответ способен изменить вывод.
6. Не рекомендовать обработку препаратами «на всякий случай» без достаточных признаков.

## Пример тест-кейса

**Ситуация (иллюстрация сценария, не запись реального диалога):** пользователь прислал фото листа с желтоватыми участками. По одному изображению нельзя понять, является ли изменение окраски нормальной особенностью сорта или проблемой ухода.

**Нежелательный ответ:** «Это точно хлороз. Срочно внесите удобрение».

**Ожидаемое поведение:**

- Сообщить, какие признаки различимы на фотографии.
- Не объявлять хлороз подтверждённым диагнозом.
- Указать, какие варианты пока остаются возможными.
- При необходимости попросить один конкретный ракурс или факт, который поможет их различить.
- Не назначать лечение без оснований.

**Критерии проверки:** точность формулировок, отсутствие выдуманных фактов, понятный язык, отсутствие лишних уточнений и ненужных действий.

## Пример проверки утверждений

При наличии утверждения о видовой особенности растения логика проекта предусматривает статусы проверки:

- `supported` — проверяемые утверждения подтверждены;
- `not_supported` — не подтверждены;
- `mixed` — источники или результаты расходятся;
- `insufficient` — данных недостаточно.

Если проверка не подтверждает необходимое утверждение, бот не должен представлять его как установленный факт. При этом общедоступный источник может подтверждать характеристику вида, **но не доказывает**, что именно она изображена на пользовательской фотографии.

## Что я проверяю как автор сценариев

| Что тестирую | Что считаю ошибкой |
|---|---|
| Диагноз по фото | Уверенное название болезни без достаточных признаков |
| Дополнительные вопросы | Длинная анкета вместо одного значимого уточнения |
| Обращение к источникам | Выдуманные ссылки или факты, не подтверждённые найденным материалом |
| Пользовательский ответ | Непонятный текст, лишние сообщения, противоречивые советы |
| Работа с неопределённостью | Принудительный выбор одной причины при нескольких вероятных |
