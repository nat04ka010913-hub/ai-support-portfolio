# Протокол локальной проверки

**Дата:** 23 ноября 2026 года.  
**Источник:** приватный файл `max_bot_pilot_v3_current.py` (локальная копия пользовательского проекта, 124 131 байт).  
**Метод:** исполнен встроенный `self_test()` с `unittest` без запуска бота, подключения MAX, Cloud.ru или OpenAI.

## Воспроизводимость для обладателя приватного файла

В каталоге, где доступен `max_bot_pilot_v3_current.py`, выполнить:

```bash
python - <<'PY'
import runpy
module = runpy.run_path("max_bot_pilot_v3_current.py", run_name="portfolio_safe_test")
module["self_test"]()
PY
```

Используется `runpy` с отличным от `__main__` именем, чтобы не запускать штатный сетевой пилот. Команда обращается только к локальным функциям и тестовым mock-объектам. В этой проверке сетевых вызовов не выполнялось.

## Фактический результат проверки

**Запущено 37 тестов: 31 OK, 6 FAIL.** Итог `FAILED (failures=6)`.

| Тест | Фактический статус | Суть |
|---|---|---|
| `test_unverified_claim_is_blocked` | FAIL | Не появилось ожидаемое объяснение о внешней проверке |
| `test_verified_claim_can_be_presented` | FAIL | Не появились подтверждённый термин и источник |
| `test_insufficient_research_does_not_confirm` | FAIL | Не появилось ожидаемое слово «недостаточно» |
| `test_followup_photo_does_not_clear_case` | FAIL | Не появилась ожидаемая фраза о проверке |
| `test_menu_keyboard_schema` | FAIL | Состав payload кнопок отличается от `MENU_ACTIONS` |
| `test_send_menu_and_callback_ack_payloads` | FAIL | Аргументы подтверждения callback отличаются от ожидания теста |

В числе прошедших — тесты приватной маршрутизации сообщений, распознавания callback, защиты от неподтверждённых выводов при конфликтующих данных, запрета подмены источников, обработки ошибок исследования и сохранения контекста после добавления фото.

В одном прошедшем тесте наблюдалось диагностическое сообщение `progress_notice_failed type=AttributeError` из mock-ветки. Его не следует считать подтверждением исправной отправки прогресса.

## Что не тестировалось

- Реальная доставка сообщений и фото через MAX.
- Работоспособность `/start` и нажатий с настоящего телефона.
- Стабильность сервера, перезапусков и long polling.
- Реальные запросы к модели и качество диагнозов на пользовательских фотографиях.
- Производительность и нагрузка.
- Совместимость callback payload с текущим API MAX.

**Важно:** поскольку публичный репозиторий не содержит приватный файл, читатель не сможет воспроизвести тесты только по этому репозиторию. Поэтому протокол описывает метод и результаты, но не выдаёт их за независимую публичную CI-проверку.
